# Feature Prototype Builder

Build a Storybook-based interactive prototype from a reviewed `layout-spec.md`. The prototype uses the project's design system, layout, and component library — producing a clickable demo that BA or customers can review directly in the browser.

## Prerequisites

- `features/<feature-name>/layout-spec.md` exists and has been reviewed (generated by `feature-layout-analysis` skill)
- `features/ui-rules.md` exists — shared UI conventions
- Storybook is configured and running (`yarn storybook` or `npm run storybook`)
- Feature folder also contains the original wireframe and markdown doc for reference

## Workflow

### Step 1 — Read Layout Spec & UI Rules

1. Read `features/ui-rules.md` — load shared UI conventions (MUST read first, these rules govern all styling decisions)
2. Read `features/<feature-name>/layout-spec.md`
3. Read the original wireframe image for visual reference
4. Read the original feature markdown for business context
5. Parse the spec to identify: screens, component tree, mock data, state transitions

### Step 2 — Create Prototype Component

Create `features/<feature-name>/prototype/index.tsx`:

**Structure rules:**
- Single `'use client'` component that renders all screens
- Screens that are drawers/modals/dialogs are controlled by `useState` booleans
- Import all components from `src/components/<name>` using relative paths (`../../../src/components/<name>`)
- Import antd layout components (`Flex`, `Divider`, `Drawer`, `Dropdown`, `Pagination`, etc.) from `antd`
- Import icons using `IconSvgLocal` with `name` prop
- Use `showDialog` from `components/dialog` for confirmation dialogs (imperative API)
- Use constants from `@constant` for sizing (`K_SIZE_4`, `K_SIZE_8`, `K_SIZE_20`, `K_SIZE_24`, etc.)

**Mock data rules:**
- Embed mock data directly in the component (no API calls)
- Use the TypeScript interfaces and sample records from layout-spec.md
- Data must be realistic: Vietnamese names, proper fee codes, dates in DD/MM/YYYY, VND amounts
- Include enough records to demonstrate pagination (10–50 rows)
- Include hierarchical data if the feature uses expandable tables or trees

**Interaction rules:**
- All buttons must be clickable and trigger the correct screen transition
- Drawers open/close with proper state management
- Table rows are selectable/expandable as specified
- Filter/search fields update state (visual feedback, no actual filtering needed)
- Form fields are editable (controlled inputs with useState)
- Dropdown menus show correct options
- Confirmation dialogs appear when expected (using `showDialog`)

**Styling rules (governed by `features/ui-rules.md`):**
- MUST follow all conventions defined in `features/ui-rules.md` — buttons, search bar, drawers, form fields, spacing, status badges
- Use Tailwind CSS classes matching the project's design system
- Root wrapper: `div` with `className="p-20"` (matching existing screen pattern)
- Follow spacing conventions from ui-rules: `gap-8`, `gap-20`, `mt-12`, `mt-16`, `my-16`
- Table wrapper: `overflow-hidden rounded-radius-l border border-color-400 pb-4`
- Drawer width: `40vw` for forms, `50vw` for detail views
- Use `h-44` for input `rootClassName` (standard input height)
- Same-function buttons must look identical across all prototypes (same type, icon, text)
- View/Edit/Create/Approve modes share the same layout — only action buttons and field editability differ (see ui-rules #1)

### Step 3 — Create Storybook Story

Create `features/<feature-name>/prototype/Prototype.stories.tsx`:

```typescript
import type { Meta, StoryObj } from '@storybook/react';
import FeaturePrototype from './index';

const meta = {
  title: 'Prototypes/{Feature Code} - {Feature Name}',
  component: FeaturePrototype,
  tags: ['autodocs'],
  parameters: {
    layout: 'fullscreen',
    docs: {
      description: {
        component: '{Brief description of the feature prototype}',
      },
    },
  },
} satisfies Meta<typeof FeaturePrototype>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Default: Story = {};
```

**Story rules:**
- Title format: `Prototypes/{Code} - {Name}` (e.g., `Prototypes/PR01 - Danh mục SPDV`)
- Layout: `fullscreen` (prototype fills the viewport, no centering)
- One default story per prototype (the component handles all screens internally via state)
- Add additional stories only if the feature has completely separate views (e.g., tabs that are independent)

### Step 4 — Verify

1. Check that the Storybook dev server picks up the new story (no build errors)
2. Visually confirm the prototype renders correctly
3. Test key interactions: button clicks open drawers, table expands, dropdowns work

If there are import errors or rendering issues, fix them immediately.

### Step 5 — Report

Present to the user:
- Storybook path to view the prototype (e.g., `Prototypes/PR01 - Danh mục SPDV`)
- Summary of screens implemented
- Any deviations from the layout spec (with reasons)
- Suggestions for improvement

## Reference: Common UI Patterns

### Toolbar (Search + Filter + Actions)
```
Flex (justify: space-between, className: mt-12)
├── Left: Flex (gap: 20)
│   ├── AppTextField (search, prefix icon, w-[250px], h-44)
│   └── ButtonBase (ghost, "Lọc nâng cao", leftIcon: IC_FILTER_OUTLINE)
└── Right: Flex (gap: 20, justify: end)
    ├── ButtonBase (ghost, "Thêm mới", leftIcon: ICON_EDIT)
    └── ButtonBase (primary, "Tải xuống", leftIcon: ICON_DROP_DOWN)
```

### Data Table with Pagination
```
div (overflow-hidden rounded-radius-l border border-color-400 pb-4)
└── AppTable (scroll: {x: max-content, y: 60vh}, expandable, rowKey)
div (relative mt-8 flex justify-center)
├── Left: TextBase ("Hiển thị X/Y bản ghi")
└── Center: Pagination
```

### Drawer Form
```
Drawer (right, 40vw, closable: false, maskClosable: false)
├── title: Flex (space-between) → Title + CloseIcon
├── body: Flex (vertical, gap: 8) → Form fields
└── footer: Flex (justify: end) → ButtonBase (primary, "Xác nhận")
```

### Action Column with Dropdown
```
Dropdown (trigger: click, placement: bottomRight, arrow)
└── menu items: [{key, label, danger?}]
└── trigger: IconSvgLocal (ICON_MORE, cursor-pointer)
```
